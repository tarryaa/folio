# folio

残しておきたい回答、画像、表を集めて整理する、日本語のクリップノートアプリです。ChatGPTのライト表示を思わせる、余白のある落ち着いた画面で使えます。iPhone 15のSafariからホーム画面に追加できるPWAです。

## 起動

ビルドやサーバー側の設定は必要ありません。`dist` がそのままWebサイトになります。ローカルで確認するときは、リポジトリのルートで次を実行します。

```bash
python3 -m http.server 4173 --directory dist
```

ブラウザーで `http://localhost:4173` を開いてください。HTMLファイルを直接開く方法では、保存やPWAの機能が正しく動作しません。

## GitHub Pagesに公開

1. このフォルダーをGitHubのリポジトリにアップロードします。`dist`、`.github/workflows/pages.yml` がリポジトリ直下にある構成にします。
2. GitHubで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` ブランチへpushするか、**Actions → Deploy folio to GitHub Pages → Run workflow** を実行します。
4. デプロイ完了後、GitHub Pagesに表示されるHTTPSのURLを開きます。通常は `https://ユーザー名.github.io/リポジトリ名/` です。

ワークフローはビルドせず、`dist` のみを公開します。別名のブランチを使う場合は、ワークフローの `branches: [main]` を変更してください。公開ページに閲覧制限がある構成は含めていません。アプリに保存したノートがGitHubへ送られることはありません。

## iPhone 15でアプリとして使う

1. 公開したHTTPSのURLをSafariで開きます。
2. Safariの共有ボタンから **ホーム画面に追加** を選びます。
3. 「folio」の名前を確認して **追加** を押します。
4. 以後はホーム画面のアイコンから起動します。最初はオンラインで開き、アプリの読み込みが完了してからオフラインで使ってください。

Webページとして開いたSafariと、ホーム画面から開いたアプリでは、iOSのバージョンや起動方法によって保存領域の扱いが異なる場合があります。普段使う起動方法を決め、移行するときはバックアップを書き出してください。

## 保存とバックアップ

ノートのデータは、利用中の端末・ブラウザーの **IndexedDB** に保存します。アカウント登録、サーバー保存、端末間の自動同期はありません。同じURLを別の端末で開いても、ノートは自動では引き継がれません。対応ブラウザーでは、複数画面からの上書きを防ぐため同じ保存領域で同時に開ける編集画面を1つに制限します。

**大事なノートは定期的にJSONバックアップを書き出し、「ファイル」などアプリの外へ保存してください。** ブラウザーのデータ消去、サイトの保存領域の削除、アプリの削除、端末変更などでローカルデータが失われることがあります。書き出したバックアップを取り込むことで移行・復元できます。取り込みは既存のノートに追加する方式です。同じID・同じ内容のノートは重複を省き、同じIDでも内容が異なるノートは別のコピーとして残します。バックアップにはノートの内容が含まれるので、保管場所にも気をつけてください。

## ChatGPTからの貼り付けについて

ChatGPTの回答をドラッグや長押しで選択してコピーし、folioの編集画面へ貼り付けます。回答全体でも、一部分だけでも扱えます。HTMLがクリップボードに含まれていれば、見出し、リスト、表、リンク、コードなどの構造をできるだけ保ちます。プレーンテキストだけの場合は、元の文字情報が貼り付けられます。

ブラウザーはコピー時に、元のページのCSS、フォント、余白、複雑な配置をすべて渡すわけではありません。そのため、**編集できる状態で、ChatGPTの見た目を完全に再現することは保証できません。** コピー元の操作やiOSのバージョンによって、画像や表のコピー結果にも違いがあります。元の見た目をそのまま残したい場合は、スクリーンショットを画像として保存してください。画像内の文字や表は、通常のテキストとしては編集できません。

外部URLの画像は、配信元の制限、URLの期限切れ、通信状態によって表示できなくなることがあります。オフラインでも確実に残したい画像は、端末から画像ファイルを追加する方法を使ってください。オフライン用キャッシュに、外部画像が自動で保存されることはありません。

## 更新とオフライン

Service Workerがアプリ本体を保存するため、一度正常に読み込んだ後は、保存済みのノートをオフラインでも利用できます。外部リンクの閲覧や外部URLの画像の読み込みには通信が必要です。

更新版のService Workerは編集中の画面を自動で再読み込みしません。新しい版が用意された場合は、folioのタブ・ウィンドウをすべて閉じてから開き直すと切り替わります。iPhoneではホーム画面のアプリも終了してから開き直してください。

アプリを変更して公開するときは、`dist/sw.js` の `CACHE_NAME` を新しいバージョンに変更します。アプリ本体のファイルを追加・削除した場合は、同ファイルの `SHELL_FILES` も更新してください。Service Workerを登録するURL、manifest、各アセットは相対パスで指定しているため、GitHub Pagesのリポジトリ配下でも利用できます。

## ファイル構成

```text
.github/workflows/pages.yml  GitHub Pagesへの公開
 dist/
   index.html               アプリの画面
   app.js / styles.css      操作・レイアウト
   editor.js / editor.css   ノートの編集
   store.js                 ローカルデータ保存
   manifest.webmanifest     ホーム画面への追加設定
   sw.js                    オフライン用アプリキャッシュ
   icons/                   アプリアイコン
```

アプリは静的ファイルで構成しています。機能の追加や画面の変更はこれらのファイルから行えます。

## 動作確認

Chromiumで日本語入力、書式付き貼り付け、画像・表、複数ブロック操作、ノートの移動・タグ編集、保存後の再表示、JSONバックアップの重複処理、不正な読み込み時の取り消し、オフライン起動を確認しています。393×852のスマートフォン表示とGitHub Pagesのサブパス構成でも確認済みです。iPhone実機のSafariでの貼り付けとホーム画面起動は、公開後に実機で確認してください。

サンプル写真はUnsplashの京都の街並みを使用しています。
